# 创作流水线标准

## 一、完整创作流水线

```
人类设计角色+场景+计划
        ↓
   Director AI（素材）
   多角色自由碰撞，产出互动草稿
        ↓
   [人工检查点 A] 确认方向
        ↓
   Screenplay Writer（剧本）
   改写为可读叙事章节
        ↓
   [人工检查点 B] 确认叙事质量
        ↓
   Story Reviewer（审阅）
   评分+反馈
        ↓
   ┌─────────────────────────────┐
   │ ≥8.5 → 人工最终确认 → 发布   │
   │ 6-8.4 → 迭代修改 → 重新审阅  │
   │ <6   → 分析原因 → 重启流程    │
   └─────────────────────────────┘
```

### 各环节职责

| 环节 | 输入 | 输出 | 职责 | 成功标准 |
|------|------|------|------|----------|
| Director AI | 角色档案+场景+计划 | `content/draft-*.md` | 角色互动的创意引擎 | 核心节拍全部触发，角色行为符合档案 |
| Screenplay Writer | 草稿+档案+约束 | `content/chapter-NNN.md` | 叙事质量的执行者 | 主角视角统一，禁用词清零，可读性强 |
| Story Reviewer | 章节+档案+约束 | `content/reviews/review-*.md` | 质量守门员 | 评分稳定，反馈可操作 |

---

## 二、修改幅度阈值

**阈值：30%**

每次审阅后，评估修改量：
- **修改量 ≤30%**：在现有稿件上迭代修改
- **修改量 >30%**：认定为**结构性问题**，停止修补，重新走完整创作流程

判断标准：
- 需要重写的段落字数 / 全文字数 > 30% → 结构性问题
- 审阅指出的 P0 问题涉及 3 个以上不同场景 → 结构性问题
- 同一个问题修改 2 轮仍未解决 → 结构性问题

结构性问题的处理：
1. 分析根本原因（Director 素材有问题？还是 Screenplay Writer 改写有问题？）
2. 如果素材有问题 → 重跑 Director
3. 如果改写有问题 → 重跑 Screenplay Writer
4. 不要在烂基础上继续修补

## 三、修改执行验证标准

每次修改后，**必须运行以下自动检查**才能进入审阅：

### 禁用词检查
```bash
grep -n '架构师\|沙箱\|延迟\|反馈\|指令\|代码\|逻辑错误\|系统故障\|视网膜\|神经元\|效率\|优化\|系统化清理' content/chapter-*.md
```
结果必须为空。

### 现代词汇检查
```bash
grep -n '肌肉\|瞳孔扩散\|血管暴起\|毛线团\|透支\|外围防线\|拼图\|增幅' content/chapter-*.md
```
如有匹配，按 style-guide.md 第四节替换。

### 法眼次数统计
法眼完整开启（不含微触发/一帧闪过）不超过 1 次/章。

### 视角切换统计
主角以外的视角切换不超过 2 次/章，每次必须有逻辑过渡。

### 修改清单逐条确认
审阅提出的每个修改点，逐条 grep 或人工确认已执行。未执行的标记为"遗漏"并补上。

**检查不通过 → 不能进入审阅。**

## 四、审阅评分锚点

为减少评分波动，每个维度定义分数段锚点：

### 角色一致性（25%）
| 分数 | 锚点 |
|------|------|
| 9-10 | 每个角色的对话可以盲猜出是谁说的。属性严格尊重。无违风 |
| 7-8 | 大部分角色保持一致，偶有1-2处语言风格微偏 |
| 5-6 | 部分角色语言风格不稳定，或有低属性角色无理由超越高属性角色 |
| <5 | 角色行为严重违反档案，像换了个人 |

### 叙事张力（25%）
| 分数 | 锚点 |
|------|------|
| 9-10 | 读者无法停下来。每个场景都推进情节或升级冲突。张力曲线完整 |
| 7-8 | 整体张力到位，有1-2处节奏凹陷但不致命 |
| 5-6 | 有明显的无事件段落（>500字），或高潮处理过于草率 |
| <5 | 大段叙事没有冲突推进，读者会走神 |

### 世界观融洽（20%）
| 分数 | 锚点 |
|------|------|
| 9-10 | 零禁用词。科幻隐喻自然融入。三国时代沉浸感完整 |
| 7-8 | 无硬禁用词，但有1-2处现代感微弱渗透 |
| 5-6 | 有禁用词残留或隐喻使用不当 |
| <5 | 多处破坏沉浸感 |

### 文学质感（15%）
| 分数 | 锚点 |
|------|------|
| 9-10 | 散文质量上乘，感官丰富，show-don't-tell 彻底 |
| 7-8 | 整体可读，偶有旁白解说或描写不足 |
| 5-6 | 叙述偏平，缺少感官层次 |
| <5 | 流水账 |

### 创意新鲜度（15%）
| 分数 | 锚点 |
|------|------|
| 9-10 | 有让人意想不到的展开。角色互动产生了真正的化学反应 |
| 7-8 | 整体不套路，有1-2个新鲜角度 |
| 5-6 | 大部分走向可预测 |
| <5 | 全程套路 |

## 五、模型分离策略

同一文本不能由同一个 agent 既修改又审阅。

| 环节 | 推荐模型 | 理由 |
|------|----------|------|
| Director AI | Opus | 创意质量优先 |
| Screenplay Writer | Opus | 文学质量优先 |
| 修改执行 | Sonnet | 执行效率优先，不需要重新创作 |
| Story Reviewer | Opus（不同 agent） | 判断力优先，独立视角 |

---

## 六、人工检查节点

| 节点 | 时机 | 检查内容 | 谁做 |
|------|------|----------|------|
| 检查点 A | Director 草稿完成后 | 确认故事走向、角色互动方向是否对 | 人类 |
| 检查点 B | Screenplay Writer 产出后 | 确认叙事质量、可读性 | 人类 |
| 检查点 C | 审阅 ≥8.5 后 | 最终确认，决定是否发布 | 人类 |

**规则：没有人工确认，不能进入下一环节。**
