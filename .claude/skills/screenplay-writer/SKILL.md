# Screenplay Writer

将 Director AI 产出的多角色互动草稿改写为可读的、叙事性强的游戏剧本章节。

## 定位

Director AI 产出的是**素材**（角色各说各话的互动记录）。Screenplay Writer 产出的是**作品**（有统一视角、有节奏、有情感的叙事文本）。

这是两个完全不同的东西。素材不能直接当成品修改。

## 工作流

### Step 1: 加载资产

读取以下文件：
- 草稿：`content/draft-<scene-id>.md`
- 参与角色的完整档案：`characters/<id>.md`
- 场景文件：`scenes/<scene-id>.md`
- 世界观：`design/worldbuilding.md`
- 风格指南：`design/style-guide.md`

### Step 2: 分析素材

从草稿中提取：
1. **事件线** — 按时间顺序列出所有发生的事件
2. **核心节拍** — 标记推动情节的关键时刻（通常5-8个）
3. **可删减部分** — 标记重复、冗余、不影响主线的内容
4. **角色交叉点** — 标记多角色相遇/碰撞的时刻
5. **情感高点/低点** — 标记张力曲线

### Step 3: 改写为剧本

以主角为主视角，将素材改写为散文体叙事。遵循以下原则：

**视角原则：**
- 以主角（通常是林一）为第一视角锚点
- 其他角色通过主角的观察、对话、互动呈现
- 允许短暂切换视角（1-2次/章），但必须有逻辑过渡
- 不允许硬切到另一个角色的独立内心世界

**叙事原则：**
- 散文体，不是剧本格式（不用角色名:对话 的形式）
- Show don't tell — 通过动作和对话传递信息，不用旁白解释
- 感官描写丰富 — 视觉、听觉、嗅觉、触觉、味觉
- 节奏控制 — 紧张段落用短句，舒缓段落可以铺开

**取舍原则：**
- 核心节拍必须保留，但可以改变呈现方式
- 配角的独立场景压缩为主角观察到的片段
- 重复的信息只保留首次出现
- 素材中的叙事节拍，只保留60-80%进入最终剧本

**字数控制：**
- 输出字数 = 素材字数 × 60-80%
- 如果素材7000字，剧本目标4200-5600字

### Step 4: 自检

改写完成后，逐条检查：

- [ ] **禁用词扫描**：对照 `design/style-guide.md` 第三节禁用词列表，grep 检查
- [ ] **现代词汇替换**：对照第四节替换参考表，检查是否有遗漏
- [ ] **法眼/系统提示次数**：统计法眼开启次数（≤1次/章，微触发不算）
- [ ] **视角一致性**：确认主角视角贯穿，切换处有过渡
- [ ] **隐喻系统**：科幻概念是否全部用古风隐喻表达
- [ ] **角色语言风格**：每个角色的对话是否符合档案中的语言特征
- [ ] **属性尊重**：低属性角色没有无理由超越高属性角色

如果自检发现问题，在输出前直接修复。不要留给审阅来挑。

### Step 5: 输出

写入 `content/chapter-NNN.md`，格式：

```markdown
---
scene: <scene-id>
characters: [<character-ids>]
based_on: draft-<scene-id>.md
date: <date>
status: screenplay
---

# 第N章·<章节标题>

[正文]
```

## 与 Director AI 的分工

| | Director AI | Screenplay Writer |
|---|---|---|
| **输入** | 角色档案+场景+计划 | Director 的草稿 |
| **输出** | 互动记录（素材） | 叙事章节（作品） |
| **关注** | 角色互动的化学反应 | 读者的阅读体验 |
| **视角** | 全知（轮流给每个角色） | 主角为主 |
| **格式** | 分节拍的互动记录 | 散文体叙事 |
| **质量** | 创意优先 | 可读性优先 |

## 常见陷阱

1. **照搬素材** — 不要把草稿段落原封不动搬过来加点描写就算改写。要从头用主角视角重新叙述
2. **过度删减** — 素材中的好对话、好细节要保留，只是换一种方式呈现
3. **忽视节奏** — 不能全程紧张也不能全程平淡。松紧交替
4. **角色扁平化** — 配角虽然通过主角视角呈现，但仍需保持立体感
